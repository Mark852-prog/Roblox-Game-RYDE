# Architecture

How the project is organised and why. Updated every milestone.

## Workflow

```
src/            Luau source code (the real game code)
assets/         Generated models: World.rbxm (map), Vehicles.rbxm (bikes)
tools/          Generators (build-world, build-vehicles) and build.sh
tests/          Automated tests, run with Lune outside Roblox
build/RYDE.rbxl The finished place file you open in Roblox Studio
```

- **Rojo** (`default.project.json`) maps folders into the Roblox game tree
  and builds `build/RYDE.rbxl`. It also sets world/lighting settings that
  scripts aren't allowed to change (Future lighting, terrain grass).
- **Lune** generates the map and bike models from code and runs the tests.
- **Selene** lints the game code (`roblox_lite.yml` is an offline std).
- `tools/build.sh` does everything in order.

The map and bikes are generated, not hand-placed: reproducible, reviewable
as text, and the bike geometry comes from the same config as its physics.
Terrain (ground, lake, hills, mountains) is generated by the server at start
because terrain voxels can't be written into a model file.

## Key decisions

### 1. Roblox standard units: 1 stud = 0.28 m, gravity 35 studs/s²
Follows create.roblox.com/docs/physics/units ("Realistic" gravity preset).
Vehicle configs use real-world units (kg, m, N, km/h); `Units` converts.
Changed from 0.35 m/stud in 0.2.0 after reviewing the Roblox docs.

### 2. Bike physics: one rigid body + raycast wheels
Roblox's own constraint wheels are unstable for two-wheelers (they jitter
and fall over), so each bike is **one physics body** (the invisible
`Chassis` box, the only part with mass) moved by forces:

| Force | Where applied | Why |
|---|---|---|
| Suspension (spring + damper, tuned in Hz) | tyre contact patch | bumps, landings, weight transfer |
| Drive / brakes / rolling resistance | tyre contact patch | below the centre of mass, so **wheelies and stoppies happen physically** |
| Lateral tyre grip | above the contact patch at centre-of-mass height | turning without tipping the body |
| Grip limit (friction circle) | per tyre, load × surface grip | wheelspin, skids, locked wheels |
| Rider weight shift | pitch torque | lean back = wheelie, forward = keep front down |
| Balance | roll controller (weak in the air) | stands in for the rider balancing |
| Aero drag | centre of mass | real top speed from power vs drag |

Ground contact uses a **sphere cast the size of the tyre** so wheels roll
up kerb edges. Forces use `VectorForce`/`Torque` constraints
(create.roblox.com/docs/physics/mover-constraints), updated every frame.

**Visual lean** is drawn by rolling the bike's visual parts and rider
around the tyre contact line (a `Motor6D`), while the physics body stays
upright. This keeps the simulation stable; the lean angle follows the real
formula tan(lean) = speed × turn rate / g, so it looks right.

`VehicleMath` holds all handling maths as pure functions, and the tests
check design goals from the real configs (top speed, 0–50 time, wheelie
and stoppie thresholds, brakes never flip the bike).

### 3. Network ownership
The server gives the rider **network ownership** of their bike
(create.roblox.com/docs/physics/network-ownership), so controls respond
instantly and the rider's computer simulates it. The server remains the
authority on: who may ride which bike (ProximityPrompt handled on the
server, owner-only), spawning, parking, and a speed sanity check (a bike
far over its top speed is taken back). Trade-off (documented by Roblox):
the owning client could tamper with its own bike's motion; damage,
rewards and police (later) will be decided on the server, not trusted
from the client.

### 4. Rider
Seated with a `Seat` (touch-sitting disabled; the server seats you). While
riding, the character is massless (the bike's mass already includes the
rider) and in a collision group that doesn't hit the world. Hands and feet
are placed with `IKControl` on each client.

### 5. Audio
All sound IDs live in `SoundConfig` (Roblox-licensed ProSoundEffects/APM
library and Roblox UI sounds). Every sound plays through one of four
`SoundGroup`s (Vehicles, Ambience, Music, UI) so the Settings sliders can
mix them. Vehicle sounds are 3D, attached to each bike, and computed on
each client from the bike's motion.

### 6. World
Terrain for ground/hills/water (generated by `WorldService`), parts for
everything built (roads, kerbs, buildings, props). Decoration (paint,
leaves, labels) is non-colliding and ignored by raycasts, following the
performance guidance in the environmental-art curriculum. Streaming is
still off (map < 5,000 parts); it will be revisited as the map grows.

### 7. UI
One theme module (colours, fonts, components, hover/click feedback) so
every screen is consistent (create.roblox.com/docs/production/game-design/
ui-ux-design). The lobby is a real 3D scene (the garage showroom) rather
than a flat picture.

## Server vs client

| Component | Side | Authoritative? |
|---|---|---|
| VehicleService: spawn, mount, ownership, parking, speed check | Server | Yes |
| WorldService: terrain | Server | Yes (replicates) |
| Remote requests (Spawn, Dismount) | Client → server | Validated, rate-limited |
| BikePhysics | Rider's client | Simulates (network owner); server checks |
| BikeVisuals, sounds, IK | Every client | Presentation only |
| Menu, HUD, settings | Client | Presentation only |
